# 项目目标文档

## 一、项目名称
轻量级Web服务保障与分布式日志AI监控平台

## 二、核心目标

### 2.1 总体目标
构建一个轻量级、容器化的日志监控平台，实现从日志采集、处理、存储到AI智能分析的完整流水线，支持5分钟内完整演示。

### 2.2 具体目标

| 目标编号 | 目标内容 | 验收标准 |
|---------|---------|---------|
| G1 | 全容器化部署 | 10个容器稳定运行，总内存≤1.7GiB |
| G2 | 域名访问 | 用户通过 kafka.subencai.cn 访问系统 |
| G3 | 统一流量入口 | 主机Nginx反向代理到容器，单端口(80)对外服务 |
| G4 | 日志采集 | Filebeat实时采集Nginx和Web应用日志 |
| G5 | 消息队列 | Kafka接收日志消息（单节点模式） |
| G6 | 日志处理 | Python消费者解析日志并存储到MySQL |
| G7 | 异常告警 | 自动检测4xx/5xx错误并创建告警 |
| G8 | 多渠道告警 | 邮箱告警、钉钉告警、前端告警 |
| G9 | AI智能诊断 | 调用DeepSeek API分析错误原因和修复建议 |
| G10 | 极简运维前端 | Vue3前端展示服务状态、日志、告警 |
| G11 | 监控可视化 | Prometheus+Grafana监控容器指标 |

## 十二、风险与应对

| 风险 | 影响 | 应对措施 |
|-----|-----|---------|
| Docker镜像拉取失败 | 无法部署 | 配置国内镜像加速器 |
| 内存不足 | 容器崩溃 | 严格限制容器内存 |
| 域名解析失败 | 无法访问 | 确认DNS配置正确 |
| 邮箱发送失败 | 告警丢失 | 配置备用告警渠道 |
| 钉钉Webhook失败 | 告警丢失 | 检查Webhook配置 |
| DeepSeek API失败 | 无AI分析 | 返回默认分析结果 |
| 网络不稳定 | 服务不可用 | 配置健康检查和自动重启 |
